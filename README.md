# Inbound_demand_forecast_portfolio — 入庫実績から需給を予測するポートフォリオ

国内の3PL事業者（物流業務を請け負う会社）が、荷主からの入庫実績のパターンをもとに、今後の入荷・出荷量を予測する試作プロジェクトです。実データは一切使用せず、ダミーデータの生成から予測モデルまで一式を成果物としています（GitHub公開前提の匿名設計）。

3PL側からは、荷主がいつ・なぜ発注したかという情報は見えません。そこで「発注の理由を推測する」のではなく、**「これまでの入庫実績のパターンから今後を予測する」**というアプローチを取っている点が設計の核心です。詳しくは [docs/design.md](docs/design.md) を参照してください。

## 1. ダミーデータの生成

```bash
python -m src.export_excel
```

`data/synthetic/inbound_demand_dummy.xlsx` に、商品マスタ・日々の入出庫実績・週次の見込み数量の3シートを書き出します。各項目の意味は [data/DATA_DICTIONARY.md](data/DATA_DICTIONARY.md) を参照してください。

## 2. 需要予測モデル・週次見込みの精度検証

```bash
python -m src.run_forecast
```

以下の3つを確認できます。

1. **商品ごとの日々の需要予測**: 従来のやり方（前週の同じ曜日の平均）と、機械学習モデルを比較すると、全体の予測誤差は18.6%から15.6%まで改善します。ただし、販売終了が近い商品については機械学習モデルの方が誤差が大きくなる（過去のデータの範囲を超えた「右肩下がりの継続」をうまく見積もれないため）という限界も正直に示しています。
2. **週次見込みの精度検証**: 荷主から提供される週次の見込み数量が、実際の数量とどれだけ合っていたかを検証します。これまで精度検証がされていなかった課題に、モデルを使わずそのまま応えるものです。
3. **荷主の見込み vs 自前モデルの比較**: 全体では自社の予測モデルがわずかに上回りますが、商品カテゴリによっては荷主の見込みの方が精度が高いケースもあり、一律にどちらが優れているとは言えない結果になっています。

結果は`reports/*.csv`・`reports/figures/*.png`に出力されます。数値の解釈の詳細は[docs/design.md](docs/design.md) 6章を参照してください。

## 3. 補充ロジック・需要パターンのシミュレーター（画面）

```bash
streamlit run app.py
```

発注のタイミングやルール（定期的に発注する方式・在庫が一定水準を切ったら発注する方式）、リードタイム、安全在庫の日数などを画面上で調整し、その結果として欠品率や在庫の推移がどう変わるかを確認できます。

以前の実装には、販売終了が近い商品の発注量を「期間全体（将来分を含む）の平均需要」から決めてしまう誤りがあり、欠品率が55〜70%まで悪化するバグがありました。発注した時点までの実績だけを使う方式に直したことでこの問題を解消した経緯は[docs/design.md](docs/design.md) 8章を参照してください。

## セットアップ

```bash
pip install -r requirements.txt
python -m src.export_excel
python -m src.run_forecast
streamlit run app.py
```

## テスト

```bash
python -m pytest tests/ -v
```

ダミーデータが矛盾なく生成されているか、発注ロジックが未来の情報を使っていないか、予測モデルが従来のやり方を上回っているか、などを自動テストで検証しています（実データ・実APIは使用しません）。
